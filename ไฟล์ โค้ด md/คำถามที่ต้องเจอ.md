# คำถามที่น่าจะเจอ + แนวคำตอบ
## Challenge 05: Scene Text Detection and Recognition

> ระดับ: ⭐ พื้นฐาน | ⭐⭐ ต้องเข้าใจโค้ด | ⭐⭐⭐ คำถามเชิงวิจารณ์ (กรรมการชอบถาม)

---

## A. ทฤษฎีทั่วไป

### A1. ⭐ Otsu กับ Iterative Thresholding ต่างกันอย่างไร
- **Otsu:** หา T ที่ทำให้ Between-class Variance สูงสุด โดยดูจาก Histogram ทั้งหมด
- **Iterative:** เริ่มจาก T₀ แล้วอัปเดต T = (μ₁+μ₂)/2 ซ้ำจนลู่เข้า
- ทั้งคู่เป็น Global Threshold และให้ผลใกล้กันเมื่อ Histogram เป็น Bimodal ชัด
- ใน TC6/TC7 ใช้ Iterative เป็นค่าตั้งต้น แล้วปรับด้วยตัวคูณ k เพราะ Pixel ตัวอักษรมีน้อยกว่าพื้นหลังมาก ทำให้ T ที่ได้ไม่เหมาะเสมอไป

### A2. ⭐ ทำไมต้องพลิกสีให้เป็นตัวดำบนพื้นขาว
Tesseract ถูกฝึกกับเอกสารพิมพ์ (ตัวดำบนกระดาษขาว) ข้อมูลรูปแบบนี้ให้ผลเสถียรที่สุด

### A3. ⭐ ทำไมต้อง Padding
ถ้าตัวอักษรชิดขอบภาพ Layout Analysis ของ Tesseract อาจตีความเป็นเส้นกรอบหรือตัดตัวอักษรทิ้ง การเติมขอบขาว 20–30 px ทำให้หาบรรทัดข้อความได้ถูกต้อง

### A4. ⭐ ทำไมต้องย่อ/ขยายภาพก่อน OCR
- Tesseract ทำงานได้ดีเมื่อตัวอักษรมีขนาดพอเหมาะ
- ใหญ่เกินไป (VOLVO ~120 px, Arturo's ~100 px) → ย่อ
- เล็กเกินไป (TC2, COAL OVEN, BEST) → ขยาย
- *(ถ้าถูกถามตัวเลขที่ "เหมาะที่สุด" ให้ตอบว่าเลือกจากการทดลอง ไม่ต้องอ้างตัวเลขตายตัว)*

### A5. ⭐ CLAHE ต่างจาก Histogram Equalization ปกติอย่างไร
- CLAHE ปรับ Histogram เป็นช่องย่อย (local) จึงเหมาะกับแสงไม่สม่ำเสมอ
- ClipLimit (0.02) จำกัดการขยาย Contrast ไม่ให้ Noise ถูกขยายตาม

### A6. ⭐ Median Filter ดีกว่า Gaussian ตรงไหน (TC1)
Median กำจัด Salt-and-pepper (จุดขาว/ดำโดด ๆ จากรอยขีดข่วน) ได้ดี และรักษาขอบตัวอักษร ส่วน Gaussian จะเบลอขอบไปด้วย

### A7. ⭐⭐ Top-hat ทำอะไร ทำไมต้องใช้ SE ขนาดใหญ่กว่าเส้นตัวอักษร
- Top-hat = f − opening(f)
- Opening ด้วย SE ที่ใหญ่กว่าความหนาเส้นจะ "ลบตัวอักษรออก" เหลือแต่พื้นหลัง
- เมื่อลบออกจากภาพเดิม จะเหลือแต่ตัวอักษร
- ถ้า SE เล็กเกินไป ตัวอักษรจะถูกนับเป็นพื้นหลังและหายไป จึงใช้ disk 15 (OPEN) และ disk 16 (strip)

### A8. ⭐⭐ Hough Transform หามุมเอียงได้อย่างไร
1. Canny หาขอบ → `hough` แปลงเป็น (ρ, θ)
2. `houghpeaks` หา 10 จุดเด่น → `houghlines` ได้เส้นตรง
3. แปลง θ เป็นมุมจากแนวนอน เก็บเฉพาะเส้นที่เอียงไม่เกิน 10° (OPEN) / 15° (Arturo's)
4. ใช้ค่ามัธยฐาน (ทนต่อเส้นผิดพลาด) แล้ว `imrotate`

### A9. ⭐⭐ Watershed ใช้ทำอะไรใน TC7 และทำไมไม่ใช้กับทุกตัวอักษร
- ใช้แยกตัวอักษรที่ติดกันใน Strip (เช่น ตัวในคำ WORLD'S)
- Distance Transform → `imhmin` ลด Local minima → `watershed` ได้เส้นแบ่ง
- ทำเฉพาะ Region ที่กว้างกว่า 2 เท่าของความกว้างมัธยฐาน เพราะถ้าทำกับทุกตัว จะเกิด Over-segmentation (ตัวอักษรปกติถูกหั่นเป็นชิ้น)

### A10. ⭐ Word Confidence มาจากไหน
มาจาก Tesseract โดยตรง (`results.WordConfidences`) เป็นค่าความมั่นใจของการรู้จำคำนั้น ช่วง 0–1 เราไม่ได้คำนวณเอง

## B. คำถามรายภาพ

### B1. ⭐⭐ TC1: ทำไมใช้ Threshold 120 แทน Otsu
- เป้าหมายตอนนั้นคือหา "แผ่นป้าย" (สว่าง) ไม่ใช่ตัวอักษร
- ค่า 120 แยกป้ายออกจากฉากหลังได้ และเลือก Region ที่ใหญ่สุดอีกชั้น
- ยอมรับว่าเป็นค่าเฉพาะภาพนี้ ถ้าทำให้ทั่วไปควรใช้ Otsu

### B2. ⭐⭐ TC1: ทำไมไม่ Binarize ก่อน OCR
หลัง CLAHE + Median ภาพเทามี Contrast ดีพอแล้ว Tesseract มี binarization ภายในอยู่แล้ว การ Binarize เองอาจทำให้ตัวอักษรขาดตรงจุดที่มีแสงสะท้อน

### B3. ⭐ TC1: ทำไมอ่าน Footpath กับ To ไม่ได้
หัวน็อตบังตัวอักษรตัวแรก (Occlusion) ข้อมูลในภาพหายไปจริง Preprocessing ไม่สามารถกู้คืนได้

### B4. ⭐⭐ TC1: เงื่อนไข "ge" และ 82% ของความสูงคืออะไร
- OCR อ่านหัวน็อตด้านล่างเป็นคำว่า "ge"
- จึงตัดคำที่อยู่ส่วนล่าง 18% ของป้าย และคำว่า "ge" ทิ้ง
- *(ถ้าถูกถามว่าเป็น hard-code หรือไม่ ให้ยอมรับว่าใช่ เป็นการกรองเฉพาะภาพนี้)*

### B5. ⭐ TC2: ทำไมใช้ Opening ไม่ใช้ Closing
- **Opening** ลบจุด Noise เล็ก ๆ ที่เป็นสีขาว (ตัวอักษรเป็นสีขาวหลัง Threshold)
- **Closing** ใช้เชื่อมรอยขาด ซึ่งไม่ใช่ปัญหาหลักของภาพนี้

### B6. ⭐ TC3: ค่า 300 ใน bwareaopen มาจากไหน
ทดลองแล้ว Blob แสงสะท้อนส่วนใหญ่เล็กกว่า 300 px ขณะที่ตัวอักษร HAIR ใหญ่กว่ามาก จึงแยกด้วยพื้นที่ได้

### B7. ⭐⭐ TC4: ทำไม f_blue = B − (R+G)/2 แล้วยังต้อง mat2gray
- ค่า f_blue ติดลบได้ (สีแดง/เขียว)
- `graythresh` ต้องการภาพในช่วง [0,1] จึง Normalize ก่อน
- การกรองจริงเกิดที่ Otsu ไม่ใช่ที่เครื่องหมายบวก/ลบ

### B8. ⭐⭐ TC4: ทำไม Closing disk 2 ไม่ใหญ่กว่านี้
SE ใหญ่ไปจะทำให้ช่องในตัว O และช่องระหว่างตัวอักษรถูกปิด OCR จะอ่าน O ผิดหรือรวมตัวอักษรติดกัน

### B9. ⭐⭐ TC6: ทำไมใช้ min(R,G) − B
- สีเหลืองต้องมี R และ G สูงพร้อมกัน → `min` บังคับเงื่อนไขนี้
- พื้นแดง (G ต่ำ) และพื้นดำจะได้ค่าใกล้ 0
- ลบ B เพื่อตัดสีขาว

### B10. ⭐⭐⭐ TC6: การลองหลายพารามิเตอร์แล้วเลือกตัวที่ดีที่สุด เป็นการ Overfit / โกงผลหรือไม่
- เกณฑ์เลือกคือ score = Σ(Confidence × จำนวนตัวอักษร) จาก OCR เอง **ไม่ได้ใช้ Ground Truth**
- จึงทำได้จริงกับภาพที่ไม่รู้คำตอบ
- แต่ยอมรับได้ว่า ช่วงค่า k / scale ที่ใส่ในลิสต์ เลือกมาจากการทดลองกับภาพนี้

### B11. ⭐⭐ TC6: Shear (slant) ทำอะไร ต่างจาก Deskew อย่างไร
- **Deskew** หมุนทั้งบรรทัดให้แนวนอน
- **Shear** แก้ตัวเอียง (italic) ที่ฐานบรรทัดตรงแต่ตัวอักษรเอนไปทางขวา โดยดึงส่วนบนไปทางซ้าย
- ลอง 0°, 10°, 20°

### B12. ⭐⭐ TC6: ทำไม COAL OVEN ไม่ต้อง Deskew
เป็นฟอนต์ Block ตั้งตรงอยู่แล้ว และใช้ charset ตัวพิมพ์ใหญ่อย่างเดียว เพื่อลดโอกาสอ่านผิด

### B13. ⭐⭐ TC7: ทำไมใช้ Chromaticity R/(R+G+B) ไม่ใช้ R channel
- R channel สูงทั้งในสีแดงและสีขาว/แสงไฟ
- สัดส่วน R ไม่ขึ้นกับความสว่าง จึงทนต่อเงาและไฟนีออน

### B14. ⭐⭐ TC7: BEST หาอย่างไร
1. หาวงกลมแดง (Region แดงที่ใหญ่สุด)
2. Convex Hull ให้เป็นวงเต็ม
3. หาวงในรัศมี 93%
4. ตัวอักษร = อยู่ในวง และไม่ใช่สีแดง
5. กรอง Region เล็ก แล้วขยาย 1.5 เท่า

### B15. ⭐⭐ TC7: Tc ถ้าไม่อยู่ใน 0.40–0.60 ให้เป็น 0.47 ทำไม
เป็นการป้องกันกรณี Histogram ไม่แยก 2 กลุ่มชัด Iterative อาจได้ค่าที่ไม่สมเหตุสมผล จึงใช้ค่าสำรองที่ทดลองแล้วว่าใช้ได้

### B16. ⭐⭐ TC7: Polar Unwrapping ทำงานอย่างไร
- สร้าง Grid (r, θ) → แปลงเป็น x = cx + r·cosθ, y = cy − r·sinθ → `interp2` ดึงค่าสี
- WORLD'S อยู่ด้านบน ไล่มุมจาก 172° ลดไป 10° (ซ้าย→ขวา) แถวบนเป็นรัศมีนอก
- DONUTS อยู่ด้านล่าง ไล่ 196°→350° แถวบนเป็นรัศมีใน
- ทั้งสองแบบทำให้ตัวอักษรไม่กลับหัว

### B17. ⭐⭐ TC7: ศูนย์กลาง (143, 245) และรัศมีได้มาอย่างไร
- วัดจากภาพด้วยมือ ตรวจด้วย DEBUG figure ที่วาดวงแหวนทับภาพ
- WORLD'S ลองมุมเริ่มหลายค่า (172–188°) เพื่อลดความคลาดเคลื่อน
- งานต่อยอดคือหาวงกลมอัตโนมัติด้วย `imfindcircles` (Circular Hough)

### B18. ⭐⭐⭐ TC7: ใช้ Lexicon ช่วยแก้คำหรือไม่
- โค้ดรองรับ แต่ตั้ง `USE_LEXICON = false` ผลที่รายงานจึงเป็น OCR ล้วน
- ถ้าเปิด จะแก้คำที่ผิดไม่เกิน 2 ตัวให้เป็นคำที่คาดไว้ ซึ่งต้องระบุในรายงาน

## C. คำถามเชิงวิจารณ์ / การวัดผล

### C1. ⭐⭐⭐ ทำไมสูตร Recognition Rate ของ TC1–5 กับ TC6–7 ต่างกัน
- TC1–5 เทียบตัวอักษรทีละตำแหน่ง ถ้าตัวอักษรหายตรงกลางคำ ทุกตัวหลังจากนั้นจะเลื่อนและนับผิด
- TC6–7 ใช้ Levenshtein (edit distance) ซึ่งยุติธรรมกว่า
- *(คำตอบที่ดีกว่า: เสนอว่าควรใช้ Levenshtein กับทุก TC เพื่อให้เทียบกันได้)*

### C2. ⭐⭐⭐ ค่าเฉลี่ยในตารางสะท้อนผลจริงหรือไม่ ในเมื่อไม่นับคำที่อ่านไม่ได้
- ค่าเฉลี่ยในตารางคือ "ความแม่นยำของคำที่อ่านได้" (คล้าย Precision)
- ถ้าต้องการ "อ่านครบแค่ไหน" ควรหารด้วยจำนวนคำใน GT ด้วย (คล้าย Recall)
- เตรียมตัวเลข TC1 ไว้ตอบ: ถ้านับ Footpath/To เป็น 0% ค่าเฉลี่ยจะลดลงเหลือเท่าไร

### C3. ⭐⭐⭐ ระบบนี้ใช้กับภาพใหม่ได้ไหม
- ใช้ไม่ได้ทันที เพราะ ROI, ศูนย์กลางวงกลม และบางค่า Threshold กำหนดรายภาพ
- สิ่งที่นำไปใช้ซ้ำได้คือ "แนวคิด": Color Feature ตามสีข้อความ, Rescale, Padding, Deskew, Unwrap
- งานต่อยอด: หา ROI อัตโนมัติด้วย MSER / Stroke Width Transform / Deep Learning detector (เช่น EAST, CRAFT)

### C4. ⭐⭐⭐ Confidence สูงแปลว่าอ่านถูกเสมอหรือไม่
- ไม่เสมอ Confidence คือความมั่นใจของโมเดล ไม่ใช่ความถูกต้อง
- อาจมั่นใจสูงแต่อ่านผิดได้ จึงต้องวัด Recognition Rate เทียบ GT แยกต่างหาก

### C5. ⭐⭐ ทำไมไม่ใช้ Deep Learning OCR
- โจทย์เน้นเทคนิค Image Segmentation จากในชั้นเรียน
- ใช้ Tesseract (`ocr` ใน MATLAB) เป็นตัวรู้จำ เพื่อแสดงว่า Preprocessing ที่ดีช่วยให้ OCR แบบดั้งเดิมทำงานได้

### C6. ⭐⭐ เทคนิคไหนไม่ได้มาจากสไลด์เรียน
- Polar-to-Cartesian Unwrapping
- Shear correction
- Tesseract OCR
(ระบุไว้ในคอมเมนต์ของ test_case_7.m แล้ว)

### C7. ⭐⭐ ถ้าเลือกได้ TC ไหนยากที่สุด และติดปัญหาอะไร
TC6 หรือ TC7 แล้วเล่าปัญหาจริงที่เจอ เช่น
- Arturo's อ่านเป็นชิ้น ๆ → ต้องรวมคำ + ลอง Shear
- WORLD'S ตัว W ถูกตัดที่ขอบ Strip → ต้องลองหลายมุมเริ่ม

### C8. ⭐ ถ้ามีเวลาเพิ่มจะปรับอะไร
1. หา ROI อัตโนมัติ
2. ใช้ Levenshtein วัดผลทุก TC
3. ใช้ `imfindcircles` หาวงกลมใน TC7
4. ทดสอบกับภาพเพิ่มเพื่อดูความทั่วไป

## D. คำถามให้ "รันสด / แก้สด" ที่อาจเจอ

| คำขอ | สิ่งที่ต้องรู้ |
|:---|:---|
| "เปลี่ยน threshold ดูซิว่าผลเป็นยังไง" | TC2–5 แก้ตรง `graythresh`; TC6–7 แก้ `k_list` |
| "ไม่ย่อภาพได้ไหม" | ตั้ง `scale = 1` ใน TC4/TC5 → ผลน่าจะแย่ลง ใช้ยืนยันว่าการ Rescale จำเป็น |
| "ไม่ Padding ได้ไหม" | ตั้ง `pad_size = 0` (TC3–5) แล้วดูผล |
| "โชว์ Hough หน่อย" | ตั้ง `DEBUG = true` ใน TC6 หรือ TC7 |
| "เปิด Lexicon ดู" | ตั้ง `USE_LEXICON = true` ใน TC7 |

> ซ้อมรันกรณีเหล่านี้ไว้ก่อน 1 รอบ จะได้รู้ผลล่วงหน้าและอธิบายได้ทันที
